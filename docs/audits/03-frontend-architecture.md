# Auditoría Técnica: Arquitectura Frontend (`frontend/`)

Alcance revisado: `frontend/src/` (`views/`, `components/`, `stores/`, `composables/`, `utils/`, `router/`, `assets/`), `frontend/package.json`, `frontend/tsconfig*.json`, `frontend/eslint.config.ts`, `frontend/vite.config.ts`, `frontend/vitest.config.ts`, `frontend/playwright.config.ts` y `frontend/e2e/helpers/mockBackend.ts`.

## ✅ Lo que está bien hecho

- **Tipado estricto en TypeScript:** En todo `frontend/src/` (excluyendo `__tests__/`) hay **cero** usos de `: any`, `as any`, `<any>`, `@ts-ignore`, `@ts-expect-error` o `eslint-disable`. Además, `frontend/tsconfig.app.json` (L7) habilita `"noUncheckedIndexedAccess": true`, previniendo accesos inseguros a colecciones y diccionarios sin comprobación previa.
- **Separación de helpers puros en `frontend/src/utils/`:** Existen utilidades bien acotadas para parseo de mensajes (`messageParser.ts`), renderizado Markdown (`markdownRenderer.ts`), slides (`slideParser.ts`), exportación (`presentationExporter.ts`), MIME (`mimeHelper.ts`), gestos táctiles (`touchSwipe.ts`) y filtrado TTS (`ttsFilter.ts`), así como el composable reutilizable `frontend/src/composables/useTheme.ts`.
- **Escape HTML base en el renderizador Markdown propio:** `frontend/src/utils/markdownRenderer.ts` (L6-13, L233) aplica `escapeHtml` sobre el texto antes de generar etiquetas HTML, evitando inyección directa en texto plano Markdown (aunque falta defensa en profundidad con sanitización DOM).
- **Cobertura E2E desacoplada mediante mock:** `frontend/e2e/helpers/mockBackend.ts` permite ejecutar pruebas end-to-end en Playwright sin requerir los proveedores LLM reales levantados.

## Hallazgos y Plan de Ejecución

### [P1] Riesgo XSS en DiagramModal (`securityLevel: 'loose'`) y ausencia de DOMPurify en `v-html` / `innerHTML`
- **Impacto:** Seguridad
- **Target File(s):** `frontend/src/components/tools/DiagramModal.vue` (L37, L69, L319), `frontend/src/components/tools/DocumentModal.vue` (L249), `frontend/src/components/ChatPanel.vue` (L1420), `frontend/src/utils/markdownRenderer.ts` (L6-13, L233, L412), `frontend/src/utils/presentationExporter.ts` (L212)
- **Current State (Problema):** `DiagramModal.vue` inicializa Mermaid con `securityLevel: 'loose'` (L37), manipula el SVG eliminando `max-width` (L69) y lo inyecta directamente vía `v-html="diagramSvg"` (L319) sin pasar por un sanitizador SVG/HTML. Con `loose`, un diagrama generado o alterado en la conversación puede contener handlers inline (`onclick`/`onload`) o elementos activos (`<foreignObject>`/`<script>`). Asimismo, `DocumentModal.vue` (L249) y `ChatPanel.vue` (L1420) usan `v-html` confiando únicamente en el escape artesanal `escapeHtml` (`markdownRenderer.ts` L6-13, L233) sin defensa en profundidad (`DOMPurify`), y `markdownRenderer.ts` (L412) asigna `printWindow.document.documentElement.innerHTML = htmlDoc` directamente (además de `dotsContainer.innerHTML = ''` en `presentationExporter.ts` L212).
- **Desired Outcome (Objetivo):** Establecer `securityLevel: 'strict'` en Mermaid, centralizar toda inserción en `v-html` tras `DOMPurify` (perfiles diferenciados para HTML y SVG) y sustituir manipulaciones directas con `innerHTML` por APIs seguras del DOM.
- **Actionable Steps for Agent:**
  1. Cambiar `securityLevel: 'loose'` a `'strict'` en `frontend/src/components/tools/DiagramModal.vue` (L37) y añadir `dompurify` (y `@types/dompurify` si aplica) en `frontend/package.json`.
  2. Crear un módulo `frontend/src/utils/sanitize.ts` con helpers `sanitizeHtml(html)` y `sanitizeSvg(svg)` basados en `DOMPurify` y aplicarlos a `diagramSvg` (`DiagramModal.vue` L319), `renderedHtml` (`DocumentModal.vue` L249) y el HTML de mensajes (`ChatPanel.vue` L1420).
  3. Reemplazar `dotsContainer.innerHTML = ''` en `presentationExporter.ts` (L212) por `dotsContainer.replaceChildren()` y construir/sanitizar de forma segura el documento de impresión en `markdownRenderer.ts` (L412).
  4. Añadir tests unitarios en Vitest verificando el bloqueo de `<script>`, `onerror`/`onload` y `<foreignObject>` peligrosos; verificar con `npm run type-check` y `npm run test:unit`.

- **Impacto:** Arquitectura / Acoplamiento

- **Actionable Steps for Agent:**

  2. Crear servicios especializados bajo `frontend/src/services/` (`authService.ts`, `configService.ts`, `debateApiService.ts`, `historyService.ts`, `observabilityService.ts`, `audioService.ts`) y mover allí todas las llamadas `fetch()` actualmente en `stores/*.ts`, `HistoryView.vue`, `ObservabilityPanel.vue`, `SoundBar.vue` y `ChatPanel.vue`.

  4. Añadir tests unitarios sobre `httpClient.ts` (manejo de `401`, parseo de error y payloads) y ejecutar `npm run type-check` y `npm run test:unit`.
